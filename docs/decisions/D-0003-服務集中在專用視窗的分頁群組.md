# D-0003 服務集中在 PersonaHub 專用視窗的分頁群組

| | |
|---|---|
| 狀態 | 有效 |
| 日期 | 2026-11-20 |
| 決定者 | 使用者決定方向（「照建議做分頁群組」），細節由 Claude 擬定 |
| 範圍 | 外掛開啟服務的方式 |

## 決定

1. 「開啟服務的方式」新增第三個選項「PersonaHub 視窗」：所有服務都開在同一個一般視窗，收進一個名為 PersonaHub 的分頁群組。這個視窗裡已經開著的服務，再點一次就切過去，不會重複開。
2. 原有的「新分頁」和「獨立視窗」保留，預設仍是「新分頁」。
3. 視窗與群組的 id 記在 `chrome.storage.session`，瀏覽器關閉就消失。群組被拆掉或視窗被關掉時會自動重建。
4. 鎖定時沿用原本的做法，關掉所有服務分頁，視窗跟著關閉。

## 理由

使用者想要的是「把各服務的獨立視窗（像 App 的視窗）整合成一個視窗裡的頁籤」。Chrome 的 popup 型視窗沒有分頁列，沒辦法把多個 App 視窗合併成頁籤；改用一般視窗加分頁群組最接近這個需求。這個做法只用 Chrome 正式提供的 API，Bitwarden 等外掛和 DRM 播放都不受影響。

## 否決的方案

| ID | 方案 | 原因 | 重啟條件 |
|---|---|---|---|
| R-006 | 入口頁用 iframe 內嵌各服務 | 要移除各服務禁止被嵌入的防護標頭，等於拿掉防點擊劫持保護；登入 cookie 在嵌入框裡可能送不出去；DRM 與偵測機制也可能擋下來，能不能動無法保證 | 有服務實測確定能嵌入，而且願意承擔拿掉防護的風險時 |

## R-006 實測紀錄（原型，2026-11-21，使用者在真實 Chrome）

原型：入口頁分頁列＋iframe，以 DNR session rule 只對入口頁所在分頁的子框架移除 `X-Frame-Options`、CSP（預設關閉，設定頁開關）。

| 服務 | 結果 |
|---|---|
| Spotify | 可內嵌、保持登入、可播放 |
| YouTube | 可內嵌顯示、Shorts 可播放；一般影片一播放整個框架崩潰（灰底哭臉），同一支影片在一般分頁可播。排除 AdGuard 注入後仍崩潰。已改回不內嵌 |
| Netflix | 可內嵌、可播放（已登入狀態） |

R-006 目前維持否決；Spotify、Netflix 若持續穩定，再另立決策只對個別服務開放。
