## 決定

1. 新增 `.claude/agents/rules-security-reviewer.md`（只讀，Sonnet）：改到 `background.js`、`crypto.js`、`manifest.json`，或 Vault、金鑰、訊息處理相關程式時，commit 前先跑一次，對照 CLAUDE.md §6 紅線、§3 機密、決策與否決清單。
2. `.claude/settings.json` 加 PostToolUse hook（`.claude/hooks/check-on-edit.mjs`）：每次 Edit／Write 後，`.js` 跑 `node --input-type=module --check`，`manifest.json` 做 JSON 解析；失敗以 exit 2 回給 Claude 當場修。
3. `.claude/settings.json` 禁止讀取 `.env`、`.env.*`。
4. 同一個問題修正兩次仍失敗，就把現況寫進 `docs/STATUS.md`，給使用者開場白並開新對話。

## 理由

- 這個專案的主要風險在紅線（金鑰存放、加密實作、訊息來源檢查、不外送資料），改錯不會有錯誤訊息，需要專門對照。
- 語法錯誤原本要等手動跑檢查或使用者重新載入外掛才發現；編輯當下就抓，少一輪來回。
- 公開 repo，多一道防止機密進入對話的防線。
- 同一問題修兩次還錯，通常是上下文已被錯誤推論塞滿，從文件重新開始較省。
