# D-0001 以 Chrome 外掛 + 專用設定檔還原與清除登入 cookie

| | |
|---|---|
| 狀態 | 有效 |
| 日期 | 2026-11-20 |
| 決定者 | 使用者決定方向（方案 A）；架構細節由 Claude 擬定 |
| 範圍 | 整體架構 |

## 決定

1. 以 Chrome MV3 外掛實作，安裝在專用的「個人」Chrome 設定檔，藉此與公司設定檔隔離。
2. 鎖定時把各服務的 cookie 用主密碼加密存進 Vault，再清除 cookie 和站台資料；點服務時把 cookie 寫回。
3. 主密碼 → PBKDF2-SHA256（60 萬次）→ AES-GCM-256；金鑰在解鎖期間只放 `chrome.storage.session`。
4. 帳密與 TOTP 交給 Bitwarden，外掛只管 cookie。
5. 安全網：閒置或 Windows 鎖定時自動鎖定；瀏覽器啟動時一律清除；解鎖期間每 10 分鐘自動保存。

## 理由

- 痛點有兩個：每天重新登入很麻煩、要能清除個人資料。只清除（無痕或手動登出）解決不了第一個，所以要保存登入狀態。
- 專用設定檔可以和公司設定檔同時開著，也不影響開發時用的無痕視窗。
- 已安裝的 Spotify、YouTube PWA 和同一設定檔共用 cookie，還原後官方 PWA 也是登入狀態，不必改變使用習慣。

## 誰決定了哪一部分

- **使用者決定：** 第 1、2 點的方向（方案 A），專案命名 PersonaHub，服務清單。
- **使用者回「照建議」：** 第 4 點（帳密交給 Bitwarden）。
- **Claude 擬定、尚未逐項確認（有異議可改）：** 第 3、5 點的參數（迭代次數、自動保存間隔、預設閒置 15 分鐘）。

## 否決的方案

| # | 方案 | 否決原因 | 重啟條件 |
|---|---|---|---|
| R-001 | 純 PWA 平台 | 同源政策下，網頁讀寫不到其他網域的 cookie，做不到還原登入 | 無 |
| R-002 | 用 OIDC/OAuth 串接各平台 | 拿到的是 API token，不是網站登入狀態；Netflix、Friday 沒有公開 API，還要自製播放器 | 只想做自己的播放器時 |
| R-003 | 只用無痕視窗 + 密碼管理器 | 每天要重新登入所有服務；而且使用者開發時需要無痕視窗 | 無 |
| R-004 | Electron 桌面 App（第一階段） | 一般版 Electron 沒有 Widevine，Netflix、Spotify 無法播放；Windows 的 DPAPI 擋不住共用 Windows 帳號的人 | 需要比 Chrome 設定檔更強的隔離時（改用 castLabs Electron） |

**尚未驗證：** 在真實 Chrome 載入外掛；各服務 cookie 還原後是否維持登入；Uber Eats、Friday影音的登入 cookie 名稱。

## 已知限制與取捨

- 綁定 IP 或裝置的登入，還原後可能失效。
- 解鎖期間有人直接用電腦，什麼都擋不住；鍵盤側錄也防不了。
