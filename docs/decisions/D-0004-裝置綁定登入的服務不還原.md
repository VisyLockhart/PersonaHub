# D-0004 裝置綁定登入的服務不保存、不還原

| | |
|---|---|
| 狀態 | 有效 |
| 日期 | 2026-11-21 |
| 決定者 | 使用者（選方案 A），細節由 Claude 擬定 |
| 範圍 | YouTube（Google 帳號）與日後同類服務 |

## 決定

1. 服務定義加 `noRestore: true`：不保存快照、不還原 cookie，舊快照在下次保存時刪除。
2. 鎖定時照樣清除登入；解鎖後點卡片，未登入就開官方登入頁，由使用者用 Bitwarden 重新登入。
3. YouTube 套用此設定。

## 理由

使用者實測：YouTube 不論「鎖定 → 解鎖」或關閉瀏覽器重開，還原後都被登出；同樣流程 Spotify 正常，Service Worker 也沒有 cookie 寫入失敗。DevTools → Application → Device bound sessions 顯示 youtube.com 有 DBSC 工作階段 `sidts_session`，綁定 `__Secure-1PSIDTS`、`__Secure-3PSIDTS`、`__Secure-1PSIDRTS`、`__Secure-3PSIDRTS`，由 Chrome 以裝置金鑰向 `accounts.youtube.com/RotateRelyingSession` 續期。刪除後寫回的 cookie 失去綁定，Google 會作廢登入。這是刻意的防盜機制，不應繞過。

## 否決的方案

| ID | 方案 | 原因 | 重啟條件 |
|---|---|---|---|
| R-007 | 鎖定時不清除 Google 的 cookie | 鎖定對 YouTube 失去意義，違反 D-0001 的目的 | 無 |
| R-008 | 到 `chrome://flags` 關閉 DBSC | 影響整個 Chrome（含日常設定檔），降低 Google 帳號防盜保護 | 無 |
