# D-0007 入口頁放在 Chrome 側邊欄，服務開在主畫面分頁

| | |
|---|---|
| 狀態 | 有效 |
| 日期 | 2026-11-21 |
| 決定者 | 使用者（實測後同意），細節由 Claude 擬定 |
| 範圍 | 主要使用方式；修訂 D-0006 |

## 決定

1. 工具列按鈕改開 Chrome 側邊欄（`hub.html?panel=1`）；視窗不支援時退回入口頁分頁。
2. 側邊欄點服務：主畫面已有該服務分頁就切過去（登入過期才改導登入頁），否則開新分頁（空白新分頁直接取代）。不收進分頁群組（見下方後續）。
3. 側邊欄標示主畫面目前的服務，跟著分頁切換更新。
4. 專用設定檔另裝 `theme/` 深色主題，讓分頁列、工具列、側邊欄標題列與入口頁一致。
5. 分割畫面（D-0006）保留為設定頁的開啟方式之一，不再是主要做法。

## 理由

- 使用者不接受分割畫面的分隔線外觀，且入口頁窗格底部的網址標籤一按 ✕ 就拆掉分割。
- 2026-11-21 實測側邊欄：放左邊、解鎖、切換、標示、關閉後叫回都正常。服務都是一般分頁，框架偵測、DRM、DBSC 不受影響，切換時分頁保留（播放不中斷）。

## 主題為什麼不自動切換

- Chrome 沒有讓擴充功能直接設定主題顏色的 API（`theme` API 只有 Firefox）。
- 主題必須是獨立、沒有程式碼的擴充功能，不能和 PersonaHub 合併。
- 理論上可用 `management` 權限啟用／停用另一個主題擴充功能，但那是「管理所有擴充功能與主題」的高權限，而且主題對整個設定檔生效。
- 這個設定檔只給 PersonaHub 用，主題裝一次就永久生效，自動切換沒有實際效益。

## 否決的方案

| ID | 方案 | 原因 | 重啟條件 |
|---|---|---|---|
| R-011 | PersonaHub 以 `management` 權限自動切換主題 | 高權限換不到效益（專用設定檔主題可常駐） | 使用者改在日常設定檔使用 PersonaHub 時 |

## 後續

- 2026-11-21：原本把服務分頁收進 PersonaHub 分頁群組，但新版 Chrome 會自動儲存每個群組並釘到書籤列，每次鎖定後重建就多一個；外掛沒有 API 刪除或重用已儲存群組。使用者決定拿掉側邊欄的分頁群組。D-0003 的「PersonaHub 視窗」模式仍有同樣現象。
